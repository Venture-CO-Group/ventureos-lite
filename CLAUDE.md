# CLAUDE.md — Venture OS Lite

Internal AI-assisted sales & delivery workspace for Venture CO Group. **Self-hosted on the owner's own server via Docker Compose.** Read `docs/spec.md` (source of truth for features) and `docs/plan.md` (phases) before large tasks. The UI reference is `docs/prototype.html` — match its look exactly.

## What this is
Single workspace for a BDR: find businesses (Google Places prospecting, LinkedIn paste, manual), audit their websites, score against ICP, draft outreach (human sends — or, in the Outbound Motor, human approves and the system sends from the BDR's Gmail), manage pipeline/inbox/meetings, generate quotes → contracts → completion certificates, email them via Mailgun, invoice via Számlázz.hu. Multi-workspace (multi-company), RBAC + granular grants. English UI.

## Stack (do not deviate without asking)
- Next.js 15 (App Router) + TypeScript strict + Tailwind
- **Database: `DB_FLAVOR` decides.**
  - `postgres` (recommended): Postgres 16 in Docker; **tenancy enforced with Row-Level Security at the DB level** AND the Prisma tenant guard (belt and braces).
  - `mysql`: MySQL 8 in Docker; no RLS exists, so **tenancy is enforced exclusively by the mandatory Prisma tenant-guard client extension** — every query on business tables is auto-scoped to the session's workspace_id; raw queries on business tables are forbidden; an isolation test must prove it cannot be bypassed.
- ORM: Prisma (schema written to work on both flavors: no Postgres-only column types)
- Auth: **Auth.js (NextAuth) credentials provider** — bcrypt passwords, TOTP 2FA (otplib + QR enrollment), server sessions in DB, rate-limited login
- Jobs/cron: **BullMQ + Redis** (Docker service) for scheduled and background work (follow-up timers, wake-ups, Signal Engine, digests, anonymization)
- Anthropic API server-side only (claude-sonnet-4-6 for writing-quality tasks, claude-haiku-4-5 for classification/summaries) — never expose the key to the client
- Mailgun EU (transactional domain; separate cold-email domain in Phase 5)
- Playwright worker (own Docker service) for website audits + PDF rendering (headless-Chrome print from HTML templates — one pipeline for audits/quotes/contracts/certificates)
- Files (PDFs, screenshots): local volume `/data/files`, served through authenticated routes; included in backups
- Deployment: Docker Compose (`app`, `db`, `redis`, `worker`, `caddy`) — **Caddy** reverse proxy with automatic HTTPS. Nightly DB + files backup script to a second location.

## Hard rules
1. **Tenancy first.** Every business table has `workspace_id`. The Prisma tenant guard is mandatory on both DB flavors; on Postgres, RLS policies as well. Never write a query that could cross workspaces; never bypass the guarded client.
2. **No automated outreach.** The system never sends LinkedIn messages or unsolicited emails on its own. Transactional email sends only on explicit user action. Cold email module ships disabled behind a counsel-sign-off gate. Outbound Motor mail is sent by the scheduler only after a named user explicitly approved that exact text (rule 6, second half), and its sender is gated on the same counsel sign-off — the approval is the user action; the scheduler only spaces the sends.
3. **Claude is frugal.** No AI calls on page load or save. Manual triggers only — with one exception: the Outbound Motor's per-candidate draft (and follow-up) may be generated by the nightly scheduler, and only for a candidate that already passed every deterministic step including the hook check (rule 10), within the workspace daily cap. Haiku by default; Sonnet only for research cards, outreach drafts, meeting briefs, weekly analysis. Cache research/audit/classification results. Every call goes through the budget middleware (per-workspace daily USD cap) and is logged to `ClaudeUsage`.
4. **No AI in legal-document rendering.** Quotes/contracts/certificates render from versioned templates + variables only. Every legal doc carries a DRAFT watermark until an Owner finalizes it (audited action).
5. **Score gate.** Leads with ICP score < threshold (default 3) cannot enter the Contacted stage. Enforce in the API layer, not just UI.
6. **Human-control guardrail — two halves, do not merge them.**
   - **LinkedIn outreach and the Outreach Studio (spec §4.6), and every other Claude-drafted message not listed below: UNCHANGED.** A Claude-drafted message cannot be marked Sent without human modification.
   - **Outbound Motor approval path only (spec §4.43.8–9):** explicit human approval of the visible text — the exact message, signature included, as it will be sent — satisfies human control and replaces the mandatory-edit requirement. There is no auto-approve, no approve-unseen bulk action, and follow-ups go through the same queue. This exception applies to nothing else: not to LinkedIn-queue items handed off from the motor, not to the Outreach Studio, not to Cold Email campaigns, not to automation drafts.
7. **Grants over roles.** `documents.*` and `templates.*` capabilities are grants checked per user per workspace; default Owner-only. Check grants server-side on every mutation.
8. **Audit log** every grant change, export, delete, watermark removal, invoice submission.
9. **GDPR:** data stays on the EU server, hard-delete lead erasure within 72h (cascade derived data), 12-month inactivity anonymization job, backups honor erasure.
10. **Hook gate — generation time only.** The motor may not generate or queue a machine-written outbound draft without at least one concrete, company-specific fact — an audit finding or a registry data point. Enforce in code (every personalisation point must reference a stored value on the candidate), not by prompt. Candidates without a usable hook are filtered out as `NO_HOOK` before generation; an unedited machine draft that lacks a grounded fact is refused at approval and at send. **The gate does NOT apply to human-edited copy on the approval path:** once a person has edited the body (compared against the stored original), their judgement supersedes the hook, exactly as approval supersedes the mandatory edit (rule 6), and the edited draft sends on approval alone. Hook status is shown to the reviewer as information — never as an error that blocks sending an edited draft. Rule 13 still applies to every text.
11. **Sending domains.** Cold outbound sends only from `fanni.viragh@ventureco.agency` (Google Workspace, Gmail API). `mg.ventureco.group` is transactional-only; `cold.ventureco.agency` is the Mailgun bulk channel. No code path may send cold mail from the `.group` domain — assert the from-domain at send time and refuse, don't warn.
12. **Cégadat quota.** Detail lookups (`/v1/detail`) are a finite monthly budget — 5,000 on the Haladó plan. Every consumer checks the daily allocation before calling, caches the result for 90 days (a cache hit never consumes quota), and on exhaustion degrades by pausing (typed `QuotaExhausted`, resume next run) — never by erroring. `/v1/search` is unlimited but still rate-limited politely.
13. **Reference companies.** Every Product reference carries `isClient`. Only a true client (`isClient = true`) may be named in outbound copy; a targeting-pattern reference never may. Drafting reads references only through the typed nameable-references accessor.

## Conventions
- `src/app` routes, `src/modules/<domain>` for business logic, `src/lib` shared, `prisma/schema.prisma` single schema
- All Claude prompts live in `src/lib/ai/prompts/` as versioned TS constants; JSON outputs validated with zod, one repair-retry
- Server Actions or route handlers with zod input validation; no client-side secrets
- Tests: vitest for units (scoring, totals math, gates, tenant guard), Playwright for the 3 critical flows (capture→score→gate, quote→pdf→send, workspace isolation)
- Money: store HUF as integer forints, VAT computed, never floats
- Commit per task, conventional commits, migration per schema change

## Domain layout (owner decision)
- App at the ROOT of ventureco.agency; public pages on subdomains: audit.ventureco.agency, quote.ventureco.agency, meet.ventureco.agency — all A-records to the same server, routed by Caddy.
- Transactional Mailgun domain: mg.ventureco.group (already verified). Cold-email Mailgun domain: cold.ventureco.agency — fully separate reputation; never send cold mail from the transactional domain.
- Cold outbound sending identity (Outbound Motor): **fanni.viragh@ventureco.agency** — a separate Google Workspace account, sent via the Gmail API so mail sits in her Sent folder and replies land in her mailbox. Keeps the `.group` reputation (quotes, contracts, invoices) isolated from cold mail. The existing `.group` mailbox remains for existing clients.
- Three sending lanes, never crossed: `mg.ventureco.group` = transactional (Mailgun); `cold.ventureco.agency` = cold bulk campaigns (Mailgun); `fanni.viragh@ventureco.agency` = approved 1:1 cold outbound (Gmail).
- Cold guardrails remain strict: daily cap starting 10/day, recipient quality gate (audit score or verified signal), plain-text-first, instant suppression, circuit breaker on bounce >3% or any complaint.
